### 怎样观测和纠偏

借用钱学森《工程控制论》的工程视角，把开发目标、输入、可观测状态、反馈和纠偏落实到协作与验收。每次变更都应能沿这条链回查。

| 项目 | 本仓库的检查点 |
| --- | --- |
| 输入 | PDF 槽、圈选、问题 |
| 输出 | 候选槽、边框、依据和可复用结论 |
| 可观测验收 | 同一测试槽返回同一个 key 和框，复用模型调用数为 0 |
| 偏差处理 | 定位槽号漂移时同时记录索引键、导出键和闭包键。用混排 OCR 样本复现，变更标识前先确定历史缓存迁移方式。 |

进入 `docuverse/`运行以下命令。当前离线夹具覆盖A1 定位、正常检索、闭包复用、排除方向和 Mock 推理。真实模型、OCR 和生产部署的行为需要有相应环境才能验证。

```sh
cd docuverse
npm ci --ignore-scripts
npm run build
npm run check:system
```

提交 PR 时附时间线编号、基线提交、实际入口、预期与实测。如果实测偏离预期，用同一输入记录最小复现并附相关台账或模型请求中的非敏感字段。行为修正通过同一检查后，将决定、代码和结果补回时间线。已发布版本出现回归时，先保留失败证据，再由维护者评估回退对应变更或修正向前。
